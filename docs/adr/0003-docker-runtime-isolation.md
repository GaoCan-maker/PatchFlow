# ADR-0003：DockerRuntime 使用只读源仓库与容器内私有副本

- 状态：有条件接受，真实 Docker 集成测试待运行
- 日期：2026-09-21
- 决策者：项目维护者

## 背景

LocalRuntime 只能用于可信临时仓库。正式 Agent 需要在执行模型选择的命令时限制宿主文件访问、网络与资源消耗，并保证任务间工作区互不污染。

## 候选方案

### 方案 A：把宿主工作区读写挂载进容器

实现简单，但容器能直接改写宿主文件；任务回滚与异常清理存在较大误操作风险。

### 方案 B：只读挂载源仓库，复制到容器私有 tmpfs

宿主源文件不受候选修改影响。每个任务有独立可写副本，容器销毁时副本一并丢弃。代价是复制耗时、tmpfs 内存占用，以及大仓库需要提高容量上限。

## 决策

采用方案 B。容器以当前非 root 数字用户运行，只读挂载单个源仓库；运行时把源仓库复制到有大小限制的 `/work/repo`，之后在容器内完成 Git、补丁、测试与 diff 操作。

默认禁止网络、只读根文件系统、移除 capabilities、禁止提权，并限制 CPU、内存和 PID。容器命令硬超时后销毁整个容器。文件读取既在宿主侧做保守路径校验，也在容器内解析真实路径并执行任务拒绝策略。

## 后果与限制

- 宿主源仓库保持只读，候选修改不会直接写回用户仓库。
- 任务间可以通过独立容器和 tmpfs 保持文件状态隔离。
- 需要预构建包含 Python、Git、pytest 和 PatchFlow 的可信镜像。
- Docker daemon、镜像供应链、内核与 Docker Desktop 本身仍处于信任边界内；容器不是绝对安全沙箱。
- 未经真实 Docker 集成验收前，不能宣称挂载、权限和超时行为已在当前 WSL 环境验证。
- 极端大量输出仍可能在宿主 CLI 捕获阶段占用内存；新增文件也尚未进入最终 Git diff。

## 重新评估条件

当真实容器测试暴露 WSL 文件权限差异，或 SWE-bench 仓库超出 tmpfs 容量时，应调整镜像和工作区存储方式，同时保持只读源仓库与独立候选副本原则。
