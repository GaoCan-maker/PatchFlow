# ADR-0001：核心 Agent Harness 不直接依赖重型 Agent 框架

- 状态：已接受
- 日期：2026-09-20
- 决策者：项目维护者

## 背景

PatchFlow 的目标之一是研究 Agent 状态机、工具协议、上下文构建、轨迹、验证器和评测策略。如果核心控制流直接建立在高级 Agent 框架的隐式抽象上，关键行为可能难以观察、替换和做公平消融。

项目未来仍需要接入不同模型供应商，也可能通过 MCP 或框架适配器复用外部工具，因此不能把“自研核心”理解为拒绝生态集成。

## 候选方案

### 方案 A：直接采用完整 Agent 框架

优点是启动快、已有模型与工具集成多。缺点是状态、重试、消息裁剪和工具调度可能由框架隐式控制，不利于严格实验和面试深挖。

### 方案 B：自研轻量核心，通过适配器接入生态

优点是关键控制流显式、轨迹完整、模块容易消融。缺点是需要自行维护基础协议和更多测试。

### 方案 C：完全拒绝第三方库

依赖最少，但会重复实现模型 SDK、数据校验和协议客户端，工程收益很低。

## 决策

采用方案 B。核心领域层和 Agent Harness 使用项目自己的稳定接口；Pydantic 等通用基础库可以使用；模型 SDK、MCP、LangChain 或其他框架只能通过边界适配器接入。

## 后果

- 状态机、事件、预算和工具调用能够完整记录和测试。
- baseline 与消融可以共享同一领域契约。
- 首期开发量会增加，必须严格限制核心接口数量。
- 外部框架升级不会直接污染领域层。

## 重新评估条件

当自研适配层的维护成本显著超过研究收益，或者某个框架能够无损暴露所需状态、轨迹和预算控制时，重新评估该决策。
