# ADR 0009：独立显式状态机与证据图工作记忆

## 状态

已采用，第五周。

## 背景

第三周三条 baseline 共享线性历史，不能在不改变实验条件的情况下直接加入分区记忆。第四周仓库定位已能输出来源和 Top-K，但失败候选、测试事实与模型根因尚无独立结构。设计文档要求状态机、可溯源 Evidence Graph、预算内上下文和结构化反思。

## 决定

1. 新增独立 `PatchFlowAgent`，不改写三条 baseline。复用现有 `AgentState` 合法迁移、预算、Runtime、manifest 与 JSONL 事件，阶段内的理解、计划、补丁和反思使用严格 Pydantic JSON 输出。
2. Evidence Graph 与轨迹分开：轨迹保存事件原件，图保存任务当前可查询投影。模型推断保留 `model` 来源，Runtime 和验证事实必须引用事件 ID；强假设状态必须由方向一致的真实验证支持，验证边需匹配候选 ID。
3. ContextBuilder 固定保留 Issue、最近失败、已改文件、主假设和被否定方案；低优先级节点按来源可信度、Issue 相关性、新鲜度和 UTF-8 成本选择，并记录选中与丢弃。容量不足时失败而非偷偷移除反证。
4. 第五周每轮只维护一个候选；失败后回滚 Runtime 工作区并通过结构化反思回跳。第六周再引入候选隔离、并行和分层验证。
5. 真实入口与 baseline CLI 分离，强制 Docker 和 `--allow-api-spend`；自动测试只使用 FakeModel，不读取或发送 API key。

## 后果与限制

状态、事实与推断可以分别审计，失败方案在后续上下文中保持可见。额外成本是模型每个阶段至少一次请求，严格 JSON 兼容性需要真实服务联调；当前只给出内部公开测试结论，不能声称隐藏测试通过或真实模型修复率提升。单候选方案也尚不能评估候选搜索收益。
